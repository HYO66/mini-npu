# Mini NPU Simulator

## 1. 프로젝트 소개

Mini NPU Simulator는 2차원 행렬의 MAC(Multiply-Accumulate) 연산을 수행하고, 두 종류의 필터(Cross, X)를 비교하여 입력 패턴을 판정하는 Python 콘솔 프로그램입니다.

본 프로그램은 다음 두 가지 실행 모드를 제공합니다.

- **모드 1:** 사용자가 직접 3×3 필터와 패턴을 입력하여 MAC 연산 및 판정을 수행합니다.
- **모드 2:** `data.json` 파일에 저장된 다양한 크기의 필터와 패턴을 불러와 자동으로 분석하고 PASS/FAIL 결과를 출력합니다.

## 3. 구현 내용

### 3-1. 라벨 정규화

필터의 라벨 표기 방식이 서로 다르더라도 동일한 기준으로 비교할 수 있도록 라벨 정규화 함수를 구현했습니다.

| 입력 라벨 | 정규화 결과 |
|---|---|
| `+` | Cross |
| `cross` | Cross |
| `X` | X |
| `x` | X |

대소문자 및 앞뒤 공백을 제거한 후 표준 라벨인 `Cross`, `X`로 변환합니다.

지원하지 않는 라벨은 `None`을 반환하여 잘못된 필터 데이터가 사용되지 않도록 처리합니다.

### 3-2. MAC 연산 구현

MAC(Multiply-Accumulate)은 입력 패턴과 필터의 동일한 위치에 있는 원소를 곱한 후 모든 결과를 누적하는 연산입니다.

외부 벡터화 라이브러리를 사용하지 않고, 중첩 반복문을 이용하여 직접 구현했습니다.

```python
def mac(pattern, filter_data):
    n = len(pattern)
    score = 0.0

    for i in range(n):
        for j in range(n):
            score += float(pattern[i][j]) * float(filter_data[i][j])

    return score
```

각 행과 열을 순회하면서 곱셈과 누적 연산을 수행하며, 최종 누적값을 반환합니다.

### 3-3. 점수 비교 및 동점 처리

Cross 필터와 X 필터의 MAC 점수를 비교하여 입력 패턴을 판정합니다.

부동소수점 연산에서 발생할 수 있는 미세한 오차를 고려하기 위해 epsilon을 적용했습니다.

```python
EPSILON = 1e-9
```

판정 기준은 다음과 같습니다.

| 조건 | 판정 결과 |
|---|---|
| 두 점수의 차이가 epsilon 미만 | UNDECIDED |
| Cross 점수가 더 큰 경우 | Cross |
| X 점수가 더 큰 경우 | X |

두 점수의 차이가 epsilon 미만이면 어느 한쪽으로 임의 판정하지 않고 `UNDECIDED`를 반환합니다.

### 3-4. 입력 데이터 검증

**모드 1 - 사용자 입력**

- 각 행에 요구되는 개수만큼 숫자를 입력했는지 확인합니다.
- 숫자로 변환할 수 없는 입력은 오류로 처리합니다.
- NaN 및 무한대 값은 허용하지 않습니다.
- 입력 형식에 오류가 발생하면 안내 메시지를 출력하고 처음부터 다시 입력하도록 합니다.

**모드 2 - JSON 분석**

- `data.json` 파일의 존재 여부를 확인합니다.
- JSON 문법 오류를 확인합니다.
- 필터 라벨의 유효성 및 중복 여부를 확인합니다.
- 필터와 패턴의 행 및 열 크기를 확인합니다.
- 숫자가 아닌 값, NaN 및 무한대 값을 검사합니다.
- 개별 패턴 분석 중 오류가 발생하면 해당 케이스를 FAIL로 처리하고 다음 케이스를 계속 분석합니다.

### 3-5. 성능 측정

`time.perf_counter()`를 사용하여 MAC 연산에 소요되는 시간을 측정합니다.

각 행렬 크기에 대해 총 10회 반복 실행한 후 평균 시간을 계산합니다.

측정 대상 행렬 크기:

- 3×3
- 5×5
- 13×13
- 25×25

측정 시간은 밀리초(ms) 단위로 출력합니다.

실패한 세 케이스의 공통 원인은 Cross 필터와 X 필터의 MAC 점수가 동일하다는 점입니다.

- `size_25_1`: Cross 4.9, X 4.9

현재 구현에서는 두 점수의 차이가 epsilon 미만이면 `UNDECIDED`를 반환하도록 설계했습니다.

따라서 위 세 케이스는 기대 결과와 실제 판정 결과가 일치하지 않아 FAIL로 처리되었습니다.

이는 동점 상황에서 임의로 Cross 또는 X를 선택하지 않도록 설정한 판정 정책에 따른 결과입니다.

동점 처리 정책의 일관성을 유지하기 위해 판정 로직을 임의로 변경하지 않았으며, 해당 세 케이스의 FAIL을 결과 리포트에 그대로 기록했습니다.

## 5. 시간 복잡도 분석

MAC 연산은 N×N 행렬의 모든 원소를 한 번씩 순회하면서 곱셈과 누적 연산을 수행합니다.

- 바깥쪽 반복문: N회
- 안쪽 반복문: N회
- 전체 MAC 연산 횟수: N × N = N²

따라서 입력 행렬의 크기가 N일 때 MAC 연산의 시간 복잡도는 다음과 같습니다.

**O(N²)**

실제 측정 결과에서도 행렬 크기가 증가함에 따라 MAC 연산 횟수와 평균 실행 시간이 증가하는 것을 확인할 수 있습니다.

예를 들어 3×3 행렬은 9회의 연산을 수행하지만, 25×25 행렬은 625회의 연산을 수행합니다.

이는 행렬의 크기가 커질수록 전체 원소를 순회하는 연산량이 제곱에 비례하여 증가한다는 이론적인 시간 복잡도와 일치합니다.

## 6. 대규모 행렬 처리 및 최적화 방안

6-1. 대규모 행렬 처리 시 예상되는 문제

따라서 행렬 크기가 증가할수록 연산 횟수와 실행 시간이 제곱에 비례하여 증가합니다.

현재 Python 구현은 일반적인 중첩 반복문을 사용하므로 대규모 행렬에서는 반복문 실행에 따른 시간 부담이 커질 수 있습니다.

6-2. 메모리 사용량 분석

Python 리스트에 숫자를 저장하는 현재 방식은 실제 숫자 데이터뿐 아니라 리스트 및 객체 관리에 필요한 추가 메모리도 사용합니다.

1000×1000 행렬 하나는 1,000,000개의 원소를 저장해야 합니다.

일반적인 64비트 환경에서 원소를 Python float 객체로 저장하면 실제 메모리 사용량은 단순한 8MB보다 상당히 커질 수 있습니다. 여기에 행렬을 구성하는 리스트의 메모리도 추가됩니다.

현재 프로그램은 패턴과 필터를 각각 메모리에 보관하므로 대규모 입력에서는 여러 행렬을 동시에 보유할 때 메모리 사용량이 증가할 수 있습니다.

6-3. 우선적인 최적화 방안

대규모 행렬을 효율적으로 처리하기 위해 다음과 같은 최적화 방법을 고려할 수 있습니다.

① 블록 처리(Block Processing)

전체 행렬을 한 번에 처리하는 대신 일정한 크기의 작은 블록으로 나누어 순차적으로 연산합니다.

예를 들어 1000×1000 행렬을 100×100 크기의 블록으로 나누면 총 100개의 블록으로 처리할 수 있습니다.

블록 단위로 데이터를 읽고 계산하면 대규모 데이터를 한꺼번에 메모리에 올려두어야 하는 부담을 줄일 수 있습니다.

② 메모리 사용량 최적화

입력 데이터를 필요한 시점에 읽어 처리하는 스트리밍 방식이나, 고정 크기 숫자 배열을 사용하는 방식을 고려할 수 있습니다.

이를 통해 Python 객체 및 리스트가 차지하는 추가 메모리 부담을 줄일 수 있습니다.

③ 연산 최적화

반복문 내부의 불필요한 형 변환과 임시 객체 생성을 줄이고, 데이터 접근 순서를 최적화하여 연산 부담을 낮출 수 있습니다.

단, 현재 과제에서는 MAC 연산을 반복문으로 직접 구현해야 하므로 벡터화 라이브러리를 사용하는 방식은 기본 구현의 대체 방법으로 적용하지 않았습니다.

6-4. 최적화 방향

현재 프로그램은 정확한 MAC 연산과 시간 복잡도 분석을 중심으로 구현했습니다.

향후 대규모 행렬을 지원할 경우 블록 처리와 메모리 효율화를 우선 적용하고, 이후 실제 측정 결과를 바탕으로 연산 구조를 개선하는 방향으로 확장할 수 있습니다.  

## 7. CPU 병렬화와 NPU 연산 병목 분석

7-1. 현재 CPU 기반 구현의 병목

현재 MAC 함수는 바깥쪽 반복문과 안쪽 반복문을 이용하여 행렬의 모든 원소를 순차적으로 계산합니다.

각 원소의 곱셈 및 누적 연산이 직렬로 수행되기 때문에 행렬 크기가 증가하면 전체 처리 시간이 증가합니다.

특히 Python의 일반적인 반복문 기반 구현에서는 다음과 같은 부분이 병목이 될 수 있습니다.

반복문 실행 및 인터프리터 처리 비용

Python 객체를 통한 숫자 접근 및 연산 비용

대규모 행렬의 메모리 접근 비용

연산량 증가에 따른 전체 실행 시간 증가

따라서 현재 구현은 알고리즘의 시간 복잡도뿐 아니라 Python 실행 환경의 오버헤드에도 영향을 받습니다.

7-2. CPU 직렬 처리와 병렬 처리 비교

직렬 처리

현재 프로그램이 사용하는 방식입니다.

하나의 실행 흐름에서 원소를 순차적으로 계산합니다.

구현이 단순하고 결과 검증이 쉽습니다.

연산량이 증가하면 처리 시간이 길어집니다.

병렬 처리

행렬의 서로 독립적인 원소 곱셈을 여러 작업으로 분할하여 동시에 처리하는 방식입니다.

여러 CPU 코어를 활용하여 처리량을 높일 수 있습니다.

행렬의 일부 영역을 각각의 작업 단위로 나누어 계산할 수 있습니다.

작업 분할, 결과 취합 및 통신에 추가 비용이 발생합니다.

Python에서는 일반적인 CPU 병렬 처리 시 프로세스 생성 및 데이터 전달 비용도 고려해야 합니다. 또한 Python의 GIL 때문에 일반적인 스레드 기반 CPU 연산 병렬화는 기대만큼 성능이 향상되지 않을 수 있습니다.

7-3. NPU 활용 시 병목 완화 방법

NPU(Neural Processing Unit)는 대량의 행렬 및 벡터 연산을 병렬로 처리하도록 설계된 전용 연산 장치입니다.

CPU에서 순차적으로 수행하는 MAC 연산을 NPU의 병렬 연산 구조로 처리하면 대규모 행렬 연산의 처리량을 높일 수 있습니다.

NPU를 활용할 때 고려할 수 있는 병목 완화 방법은 다음과 같습니다.

① 병렬 MAC 연산

여러 MAC 연산을 동시에 수행할 수 있도록 연산을 분할합니다.

② 데이터 전송 최소화

CPU와 NPU 사이에서 데이터를 반복적으로 전송하면 전송 비용이 병목이 될 수 있습니다.

따라서 입력 데이터와 필터를 가능한 한 NPU 메모리에 유지하고, 필요한 데이터를 묶어서 전송하는 방법을 사용할 수 있습니다.

③ 메모리 접근 최적화

연산 장치의 처리 속도에 비해 메모리에서 데이터를 읽어오는 속도가 느리면 연산 장치가 데이터를 기다리는 상황이 발생합니다.

이를 완화하기 위해 데이터 재사용, 메모리 접근 순서 최적화 및 블록 단위 처리를 적용할 수 있습니다.

④ 연산과 데이터 전송의 중첩

데이터를 전송하는 동안 다른 데이터의 연산을 수행하도록 작업을 구성하면 전체 처리 시간을 줄일 수 있습니다.

7-5. 결론

현재 Mini NPU Simulator는 CPU에서 반복문을 이용해 MAC 연산을 직접 수행하는 소프트웨어 시뮬레이터입니다.

따라서 실제 NPU 하드웨어의 병렬 처리 성능을 측정하는 프로그램은 아닙니다.

현재 구현은 직렬 처리 구조를 기준으로 MAC 연산의 정확성과 시간 복잡도를 확인하는 데 목적이 있습니다.

향후 실제 NPU 환경으로 확장한다면 병렬 MAC 연산, 블록 단위 데이터 처리, 메모리 접근 최적화 및 CPU-NPU 간 데이터 전송 최소화를 통해 대규모 행렬 처리의 병목을 완화할 수 있습니다.
